# 南京线体界面项目代码开发规范

## 1. 核心开发原则 (Global Rules)
- **回复与注释语言**：始终使用 **中文** 进行交流和代码注释。
- **确认机制**：在删除文件/目录、安装新依赖前，必须获得用户许可。

## 2. 后端开发规则 (C# / .NET)
- **命名规范**：遵循标准 `PascalCase`（大驼峰）命名规范。
- **异步编程**：必须全程使用 `async/await`，禁止阻塞线程。
- **通信枢纽**：SignalR Hub 的方法定义需保持精简，核心逻辑应沉淀在 `Services` 层。
- **错误处理**：针对硬件 TCP 连接，必须有完善的 Try-Catch 捕获机制，并记录详细日志。

## 3. 前端开发规则 (Vue 3 + TS)
- **API 风格**：统一使用 `Vue 3 <script setup>` 组合式 API。
- **类型安全**：
  - 禁止使用 `any` 类型。
  - 对 MES 返回的 JSON 数据，必须在 `src/types/` 中定义完整的接口。
- **网络逻辑**：
  - 发送至 MES 的请求需通过 `src/services/` 封装。
  - 对于与本地后端的 SignalR 通信，需在组件卸载时正确销毁监听。
- **样式指南**：
  - 推荐使用 Tailwind CSS。
  - 保持“工业风”深色调主题，使用 CSS 变量管理颜色。

## 4. 业务逻辑特有规则
- **扫码逻辑**：扫码枪输入通常以 `Enter` 结束，需在 `handleScan` 层面做好防抖和输入清理。
- **仿真优先**：为了方便脱离硬件环境测试，新功能开发时需同步在 `SimulatorControl.vue` 或 `handleScan` 的 Mock 逻辑中添加对应的模拟实现。
- **IO 安全**：调用 `writeSignal` 发送放行信号是业务的最后一步，必须在确认所有物料和定扭数据均已保存后执行。

## 5. 项目提交规范
- 任何 UI 布局的调整，必须确保在 `1920x1080` 分辨率下无遮挡显示（产线工位机标准）。
- 修改 `Program.cs` 路由或端口配置前，需同步检查前端的全局配置文件。
