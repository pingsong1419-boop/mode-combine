# MES 工序扫码与定扭集成系统 (南京线体) 项目理解文档

## 1. 项目背景与目标
本项目（南京线体标准界面）是一个集成化生产辅助系统，主要部署于工厂车间的工序站点。其核心目标是实现**工序防错**、**物料校验**以及**定扭矩工具的自动化集成控制**。通过连接 MES 系统和硬件控制器，确保生产过程严格遵循工艺路线。

## 2. 核心功能模块

### 2.1 工单与工艺查询
- **扫码触发**：操作员扫描产品条码，前端通过 `handleScan` 触发业务逻辑。
- **MES 对接**：
  - 调用 `GetOtherOrderInfoByProcess` 获取工单详情。
  - 调用 `GetTechRouteListByCode` 获取该工单需经历的完整工艺步骤（WorkSeqList）。

### 2.2 物料防错验证 (`MaterialScanner.vue`)
- 依据 MES 返回的 BOM 清单，要求操作员扫描物料条码。
- 系统自动比对扫描值与预设清单，防止错漏装。

### 2.3 定扭交互集成 (`TorqueInteraction.vue`)
- **硬件连接**：通过底层 .NET 服务（TCP/IP）维持与定扭控制器（如 Desoutter）的长连接。
- **Open Protocol 协议**：支持下发 PSet (MID 0018)、工具使能/禁用 (MID 0042/0043) 以及接收扭矩/角度完成报文 (MID 0061)。
- **判定矩阵**：前端根据工艺参数自动展开螺栓作业矩阵，实时填入测量值并判定 PASS/FAIL。

### 2.4 集成输出 (`labviewSignal.js`)
- 测试完成后，系统汇总物料及定扭结果。
- 通过 `writeSignal` 方法向外部系统（如 LabVIEW 上位机或 PLC）发送放行信号。

## 3. 架构设计

### 3.1 跨平台通信架构
- **前端 (Vue 3)**：负责 UI 展示、扫码逻辑处理及 MES API 交互。
- **后端 (.NET Core)**：作为“通信桥梁”驻留本地。
  - **SignalR (WebSocket)**：将底层硬件的实时报文（如扭矩值）推送至前端。
  - **TCP 客户端**：直接与定扭控制器的 4545 端口通信，处理 MID 指令。

### 3.2 仿真系统
- 项目内置了强大的仿真逻辑（输入 `MOCK-` 开头的条码），可在无硬件连接的情况下测试整个业务闭环。

## 4. 关键目录说明
- `backend/MesScanner.Backend/`: 通信桥梁服务端源码。
- `src/services/mesApi.ts`: 封装了所有厂内 MES 的 HTTP 请求。
- `src/types/mes.d.ts`: 严格定义了 MES 返回值的复杂嵌套结构。
- `src/utils/labviewSignal.ts`: 外部 IO 信号推送工具类。

## 5. 开发后续方向
- **异常重连机制**：增强 TCP 链路的自动断线重连逻辑。
- **本地存储缓存**：在 MES 服务器宕机时提供离线扫描缓存能力。
- **多设备支持**：目前的控制器适配主要针对 Desoutter，后续可扩展至 Atlas Copco 等。
